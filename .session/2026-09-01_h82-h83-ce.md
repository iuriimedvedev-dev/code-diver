# H-82 / H-83 — cross-encoder rerank fixes (implementation, not yet measured)

**Status: implemented, unit-tested, arms ready to run. No benchmark numbers yet.**

Funnel context (WHERE-79): the CE stage takes 34 graph-file candidates, documents truncated at
`max_document_chars: 850`, outputs top-10. 9 gold files die at this stage in two distinct modes:
sigmoid saturation ties at the cut boundary (SafeDeleteProcessor lost at rank 12 with 0.9979 vs
cut@10 0.9979) and truncation victims scored near zero (FoldingModelImpl 0.088,
PluginManagerCore 0.194). Global expansion (1600 chars / 80 candidates) is a measured dead end.

## Flags (all under `cross_encoder_rerank:`, all default OFF = bit-exact current behavior)

| flag | default | meaning |
|---|---|---|
| `rank_by_raw_logits` | `false` | H-82: rank by inverse-sigmoid (logit) of the provider score. The llama.cpp `/v1/rerank` endpoint only exposes the sigmoid `relevance_score`, NOT the raw model logit, so this is `log(p/(1-p))` with a 1e-7 clamp. Monotone — it cannot reorder genuinely distinct probabilities; it un-squashes the saturated top so downstream epsilon comparisons see real distances. |
| `tie_break_by_fused_score` | `false` | H-82: CE scores within `tie_break_epsilon` of each other (adjacent-chained groups on the descending list) are reordered by the incoming fused graph-file score instead of arbitrary provider/insertion order. |
| `tie_break_epsilon` | `1e-4` | tie width for the above. |
| `second_pass_enabled` | `false` | H-83: after the first pass, candidates scoring below `second_pass_score_floor` get their documents rebuilt at `second_pass_max_document_chars` and rescored in one extra CE call; final score = `max(first, second)`. High first-pass scorers are untouched, so distractors are not inflated. |
| `second_pass_score_floor` | `0.3` | retry threshold. |
| `second_pass_max_document_chars` | `2400` | expanded budget for retried documents only. |
| `second_pass_candidate_cap` | `0` (no cap) | latency guard: caps the retry batch, keeping the sub-floor candidates with the best base-fusion ranks. |

Side effect when any flag is on: the provider is asked for scores for the FULL candidate window
(`top_n = len(candidates)`) instead of `min(limit, candidates)` — both hypotheses need scores past
the cut. With all flags off the historical `top_n` is reproduced exactly.

Robustness: a second-pass provider failure keeps the first-pass scores (traced as
`cross_encoder_rerank_second_pass_error`), it does not degrade to base order. Successful second
passes emit a `cross_encoder_rerank_second_pass` trace event with retry count and improved count.

## Arms

- `configs/intellij/intellij-h82-ce-logits.yml` — champion copy + `rank_by_raw_logits`,
  `tie_break_by_fused_score`, `tie_break_epsilon: 0.0001`. Suite `h82-ce-logits`.
- `configs/intellij/intellij-h83-ce-twopass.yml` — champion copy + `second_pass_enabled`,
  floor 0.3, 2400 chars, cap 24. Suite `h83-ce-twopass`. H-82 flags deliberately OFF here so the
  second pass is measured in isolation; the mechanisms are complementary (saturated top vs
  near-zero bottom) and can be combined in a follow-up arm if both win alone.

`intellij-h66b-champion.yml` untouched.

## Latency honesty (H-83)

On hard WHERE queries most of the 34-candidate window scores below 0.3, so the uncapped second
pass would nearly double CE calls at ~2.8x tokens/doc. The arm caps the retry batch at 24; expect
roughly +0.5-1.5x CE stage latency on affected queries, ~0 on confident ones (empty retry set).
`skip_when_top_margin_at_least` and the `<=1 candidate` early-outs still bypass everything.

## Expected effect

~4-6 WHERE-79 cases at the CE stage: 1-2 tie/saturation losses (H-82, e.g.
where-safe-delete SafeDeleteProcessor) and up to 4 truncation victims (H-83, e.g.
where-code-folding FoldingModelImpl, where-plugin-loading PluginManagerCore). Watch for H-83
regressions where a rescued distractor overtakes gold sitting at 0.3-0.5.
