# Code Explanation Challenge — Итоговый отчёт

**Дата**: 2026-06-10
**Датасет**: CodeXGLUE code-to-text-python (100 функций)
**Judge модель**: Vertex Gemini 3.1 Flash Lite
**Embedding модель**: Qwen3-Embedding-0.6B (локально, порт 8001)

## Методология

### Этапы

1. **Генерация объяснений**: каждый кандидат получает на вход код функции + reference docstring и генерирует объяснение.
2. **Individual judge**: Gemini Flash Lite оценивает каждое объяснение по 7 критериям (0-4 каждый), вычисляет overall (0-5).
3. **Rich metrics**: дополнительно вычисляются F1 (token/key/bigram), embedding cosine similarity, lexical diversity (TTR), keyword overlap (TF-IDF).
4. **Пост-обработка**: сначала использовали старый (мягкий) промпт → ceiling effect (все ~28/28).
5. **Строгий промпт**: перепрогнали всех через жёсткий промпт (start at 4, deduct per issue) → реальная дискриминация.

### Промпт судьи (старый vs строгий)

| Аспект | Старый | Строгий |
|---|---|---|
| Дескриптор 4/4 | excellent; materially correct and useful | Flawless: all claims precise, traceable to code |
| Penalty generic | Нет | function вместо `validate_schema()` → вычет |
| Reference = min bar | Нет | Пропустил что-то из docstring → cap на 3 |
| Hallucination | Не выделен | 0 по критерию + critical issue |
| Evidence | Опциональна | Обязательна для < 4, ссылка на код |
| critical_issues | Может быть пустым | Не пуст, если хоть один критерий < 4 |

## Выводы

1. **Лучший overall**: `gemini-flash` (API, 1.4s, 27.84/28) — но платный, через Vertex.
2. **Лучший локальный**: `qwen4b` (2.9s, 27.72/28, 100% valid) — оптимальный баланс скорость/качество.
3. **qwen9b** (4.2s, 27.69/28) — практически идентичен qwen4b, но в 1.4x медленнее. Нецелесообразен.
4. **Gemma 26B** (13s, 26.20/28, 94% valid) — проигрывает из-за generic-объяснений (строгий судья жёстко штрафует шаблонные фразы).
5. **E4B/E2B** — неконкурентоспособны: высокий % ошибок генерации (E2B: 72-76%), низкое качество объяснений.

Старый (мягкий) промпт судьи не позволял различить кандидатов (все ~5.0/5.0). Строгий промпт дал реальную картину.

### Почему qwen4b выигрывает у qwen9b?

- Оба на MLX, оба 100% valid
- qwen4b: 2.9s vs qwen9b: 4.2s (1.4x быстрее)
- qwen4b (27.72) vs qwen9b (27.69) — разница в пределах погрешности
- Вывод: 9B параметров не дают преимущества для code explanation на этом датасете

### Rich metrics

- **EmbSim**: gemma26 и qwen4b лучшие (0.762) — семантическая близость к референсу
- **KW F1**: qwen4b лучший (0.400) — покрытие ключевых терминов из референса
- **TTR**: gemini-flash (0.657) — самое разнообразное лексическое наполнение
- **F1**: все низкие (<0.21) — генеративные объяснения не совпадают по токенам с референсом (это нормально)
