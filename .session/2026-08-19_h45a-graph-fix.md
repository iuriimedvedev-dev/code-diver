# 2026-08-19: Fix H45a Empty Retrieval Defect & Path Normalization in GraphFileRetrievalStrategy

## Context
During campaign evaluation on protogen (247 cases), H45a (`protogen-h45-search-graph-on.yml`) returned empty retrievals (`retrieved = []`) on 240/247 cases, producing a VOID arm result.

## Root Causes Identified
1. **Path mismatch / lookup misses**: Discrepancies in relative path prefixes (`./`, repository relative subpaths like `protogen/...` vs `src/...`) between vector search hits and `FileGraphCatalog` entries caused `_item_for_path` lookups to fail to match seeds.
2. **Missing candidate preservation**: When candidates were not found in the catalog or when graph propagation returned no candidates, `seed_file_scores` was dropped or produced empty results instead of falling back to vector/lexical retrieval candidates.
3. **Silent degradation without fallback**: Any propagation failure or zero-score condition resulted in empty output rather than graceful degradation to the base retrieval strategy.

## Changes Applied
- **Path Normalization & Robust Resolution**:
  - Implemented `_normalize_path` using `os.path.normpath` across catalog indexing and path queries.
  - Implemented multi-tier path matching in `GraphFileRetrievalStrategy`: exact match -> normalized match -> relative suffix/prefix component match.
  - Added thread-safe path resolution cache.
- **Graceful Fallbacks & Preservation**:
  - Retained vector hits even when absent from graph catalog.
  - Added fallback to `base_strategy.search()` on catalog errors, propagation exceptions, empty seed scores, or empty fused outputs.
- **Unit Tests**:
  - Added 7 new unit tests in `tests/unit/test_graph_file_retrieval_strategy.py` covering path normalization, relative prefix differences, propagation exceptions, and candidate preservation.
