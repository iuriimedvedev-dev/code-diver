# M5 decisions

- Verified feat/rust-full; unrelated M4 plan/session files left untouched.
- Read SPEC, runtime addendum, STATUS and DECISIONS. Existing M4 already has
  degradation notices, lazy MCP, ordering score and memory improvements.
- Use shared M3 credential/TLS policy. Never surface CE response bodies or URLs.
- Doctor runtime supervision/setup/registration checks belong to M5b.

## Implemented and validated

- Shared search/MCP/doctor flags: --embedding-query-prefix,
  --embedding-document-prefix, --embedding-dimensions, --index-metadata,
  --require-rerank[=true|false], --ce-api-key. Prefix strings preserve trailing
  whitespace. CLI > CODE_DIVER env > canonical file > profile block > defaults.
  Canonical embedding.query_prefix/document_prefix apply to index as well.
- MCP and doctor default require_rerank=true; search defaults false. Config
  search.require_rerank, CODE_DIVER_REQUIRE_RERANK and explicit flags override.
  Both CE pass failures fail strict search/MCP (MCP isError, not protocol error).
  Degraded first pass: rerank_applied=false/error and null CE scores. Degraded
  second pass: applied=true/second_pass_failed=true/error and retained CE scores.
- Search JSON has rerank_applied/rerank_second_pass_failed/rerank_error,
  meta_ranker_applied and notices. MCP text JSON array remains intact, with an
  additional warning item; structuredContent exposes results and state fields.
  Missing meta-ranker is explicit. Empty/invalid zero-tree models now reject.
- CE uses shared M3 retry policy: at most 3 transient attempts per route,
  100/200ms backoff, per-attempt CE timeout; only 404/405 route fallback.
  CE errors never include response bodies/URLs. --ce-api-key is a sensitive
  bearer header only on CE clients, not embedding/Qdrant; config dump redacts it.
- config show accepts flattened search flags, is network-free, prints effective
  JSON and redacts all four service secret fields. CE flags no longer hide file
  defaults behind Clap default strings. YAML search/CE/profile sections supported.
- [profile] scalar defaults: qdrant_url/qdrant_collection, embedding_url/model/
  dimensions/query_prefix/document_prefix (all embedding_* keys), ce_url/ce_model,
  catalog/graph_path/model/index_metadata. File section values win; no profile
  URL download or runtime model manifest loading (M5b).
- Root-relative discovery fixed. Explicit missing artifact paths are not silently
  replaced. Config-relative paths retain M3 semantics. Automatic search discovery
  no longer adopts global /tmp catalogs; explicit paths remain accepted.
- Schema-2 JSON: {schema_version:2, generated_at:<UTC Unix seconds>, collection,
  embedding:{model,dimensions,query_prefix,document_prefix}}. Index apply emits
  <catalog>.metadata.json after success and preserves it on unchanged runs.
  Profile sidecar additionally records query_prefix; old/nonmatching profiles
  require explicit migration as with M3. Discovery: explicit flag/env/config,
  then <catalog>.metadata.json, sibling index_metadata.json/rust_index_metadata.json.
  Search rejects incompatible discovered metadata before network access and
  validates returned vector dimensions. Missing automatic metadata remains allowed
  for backward compatibility; doctor treats missing metadata as FAIL.
- Doctor --json: {passed,checks:[{name,status,message,fix,elapsed_ms}]}; text emits
  PASS/FAIL/WARN plus fix per check; any FAIL exits 1. Shared credentials/TLS;
  platform, catalog/graph/model loadability, schema/profile/freshness (30 days,
  future timestamps fail), authenticated Qdrant read, collection dimensions,
  sampled stored model/dimensions, raw embedding unit norm (0.01 tolerance) and
  dimensions, short and approx2100-word/token reranking. CE opt-out maps CE
  failures to WARN. Repair hint includes --embedding --reranking --pooling rank
  --ctx-size 4096 --batch-size 4096 --ubatch-size 4096; omit --parallel.
