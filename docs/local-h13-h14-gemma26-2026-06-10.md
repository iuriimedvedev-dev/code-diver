# Local H13/H14 Gemma 26B Experiment Report - 2026-06-10

## Scope

This report covers local-only code-explanation experiments on the Protogen
answer dataset:

- Dataset: `datasets/protogen_answer_cases_100.jsonl`.
- Repository: `../protogen`.
- Embeddings: local `mlx-community/Qwen3-Embedding-0.6B-4bit-DWQ`.
- LLM roles: local `gemma-4-26B-A4B-it-qat-UD-Q4_K_XL` through llama.cpp.
- Retrieval target: file-level candidates and bounded context for the code
  explanation agent.

The goal is not just vector search. The full path under test is:

```text
question
-> LLM query planning
-> GraphRAG / hybrid file search
-> LLM shared rerank
-> bounded file context
-> LLM grounded code explanation
```

## Hypotheses

| Hypothesis | Change Under Test | Constant Controls |
| --- | --- | --- |
| H13 | Add local Gemma 26B agentic multi-query planning and shared rerank over the H12B-style documentation/code lane. | Same local Qwen embeddings, same answer model, same dataset, same context budget. |
| H14 | Add documentation chunks as first-class graph nodes and deterministic documentation graph edges. | Same H13 model stack, same calibrated hybrid weights, same GraphRAG search flow, same context budget. |

## Current Interpretation

H13 proves that simply adding a local LLM agentic query/rerank layer is not
automatically better than the stronger deterministic/context-aware retrieval
stack. Local Gemma 26B is capable, but the multi-turn agentic path is slow and
still vulnerable to confident near-misses.

H14 is testing whether text/documentation graph breadcrumbs repair that weakness.
The interrupted checkpoint suggests a possible lift in broad `file_hit` and
context precision, but the same-case trade-off is mixed. The likely next
hypothesis is not "more documentation graph everywhere"; it is route-gated
documentation graph:

- use documentation/text graph for architecture, setup, generated-code, and
  repository-orientation questions;
- keep code-first calibrated hybrid/GraphRAG for implementation and control-flow
  questions;
- preserve LLM reranking, but add stronger anti-noise constraints before
  bounded context selection.
