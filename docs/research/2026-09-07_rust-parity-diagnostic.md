# Rust/Python parity diagnostic — 2026-09-07

## Scope and conclusion

This is a bounded, paired diagnostic of the rebuilt native search release against the Python production retrieval path. It is not an independent holdout, does not establish parity, precision@10, a production speedup, or warm `p95` acceptance, and uses only three known dataset cases repeated twice per arm. The result is useful evidence for ranking and runtime behavior, not a release-quality equivalence claim.

The diagnostic completed all `12/12` arms (`3` cases × `2` repeats × `2` arms) with `0` failures. Every arm had `quality=1`, where quality means the search returned a parseable result set and the existing `ExpectedPathMatcher` could evaluate it. All repeated top-10 lists were identical within each arm/case.

The paired diagnostic was one bounded, nonpersistent Python `-B` invocation with a `700 s` outer alarm. It loaded the exact configuration once, applied the endpoint and graph overrides in memory, and built Python through `make_vector_store`, `make_embedding_provider`, and `make_retrieval_strategy`. For each seeded pair it called `strategy.search(query, 10)` for Python and launched the native command above with a per-subprocess timeout of `180 s`; it parsed native JSON timings and evaluated both result lists with `DatasetLoader` and `ExpectedPathMatcher`.

This describes the executed harness and command parameters; it is evidence documentation, not a copy-paste runnable test script. No existing evaluation script was run, no files were written by the diagnostic, and no dependency installation, build, service start, or service restart was performed during the diagnostic.

## Limitations and follow-up

- The sample has `3` known cases and `2` repeats, not an independent holdout and not `6` independent cases.
- Python per-search timing excludes one-time initialization (`1496.120 ms`); Rust wall timing includes process startup and catalog/graph/model loading, while Rust `internal_ms` excludes those costs. This prevents a certified speedup comparison.
- The native and Python paths use matching local service endpoints and catalog-provided text, but the graph artifacts are not claimed to be semantically equivalent.
- The implemented native work covers shared feature export, ranking/order fixes, retrieval `360`, CE candidate cap `34`, and exact-path representative deduplication. Independent lexical/path/symbol admission, Python file aggregation/votes, graph fan-in equivalence, and a sealed independent holdout remain outstanding.
- The native run emitted an unauthenticated Hugging Face Hub warning during Python initialization; it did not cause a failure. No `HF_TOKEN` was configured for this diagnostic.
- The evidence supports recording the observed ranking and timing differences, not declaring Rust/Python parity.
