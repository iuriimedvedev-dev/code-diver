## Hypotheses and acceptance

**R1 — selective second CE pass.** Compare `configs/intellij/intellij-h66b-champion.yml` (control) with `configs/intellij/intellij-h83-ce-twopass.yml` (floor `0.3`, expanded `2400` chars, cap `24`) on WHERE-78 and mech150. Record hit/recall/MRR/nDCG/hit@1, CE wall time, retry count, rescued and regressed cases. Accept only if WHERE recall and MRR improve, mech150 has no material regression, and latency is reported per retry bucket. Negative cases: zero retries, provider failure fallback, and a gold file already above the floor.

**R2 — relevant fragments versus file beginning.** Use the same `intellij_h52_summary_head_first_qwen` collection and compare `configs/intellij/intellij-h55-ce-file-head.yml` (meaningful head) with `configs/intellij/intellij-h62-on-the-fly-mini-index.yml` (all KDocs/signatures/declarations, best 850 chars). This tests the available proxy, not query-aware fragments. Report the same quality metrics plus per-case document provenance and CE latency. Accept only if H-62 wins on strict exact-file recall without a guard-slice loss; otherwise reject the stronger claim.

**R3 — 34-candidate recall and CE selector.** First run `scripts/replay_pool_recall.py` for pool coverage, then `scripts/replay_rerank_depth.py` with depths `34,60,80` and cuts `10,14,20` using H-91a. This requires an `evaluate-answers` report containing `results[*].query_plan`; direct `evaluate` JSON and `h83_results.json` do not suffice. Accept 34 only if pool recall is not the bottleneck and its reranked recall/MRR is non-inferior to deeper controls at the declared latency budget. Negative cases: gold absent from pool, provider error, and tie/order instability.

**R4 — latency attribution and LightGBM threads.** Export a fixed feature dump with `--dump-ce-meta-features`; benchmark model load (cold), repeated prediction (warm), and `Booster.predict(..., num_threads=N)` for `N=1,2,4,8` in a scratch script. Separately run the full pipeline with and without `scripts/keep_services_warm.py`. Report median/p95, stage shares, RSS, and quality identity. Accept a thread setting only if warm p95 improves without score drift; never attribute embedder cold-start cost to LightGBM.
